# Machine Learning Classification of Magnetospheric Regions at Lunar Distance

This repository contains the code, processed data, figures, and results from my MSci Physics project at Imperial College London.

The project uses **ARTEMIS P1/P2 (THEMIS-B and THEMIS-C)** spacecraft measurements to identify large-scale magnetospheric regions at lunar distance. It combines hierarchical **K-means clustering** with an **XGBoost classifier**, alongside a spatial analysis of the magnetopause and bow-shock boundaries.

![THEMIS magnetotail classification pipeline](docs/pipeline_overview.png)

## Project overview

The analysis is organised into five stages:

| Part | Purpose |
|---|---|
| **Part 0** | Download raw THEMIS-B/C magnetic-field and plasma measurements using PySPEDAS |
| **Part 1** | Convert the raw measurements into a common hourly dataset |
| **Part 2** | Generate region labels using hierarchical K-means clustering |
| **Part 3** | Attach spacecraft coordinates and analyse magnetopause / bow-shock geometry |
| **Part 4** | Train and evaluate an XGBoost classifier for magnetospheric region prediction |

Part 2 identifies three physically meaningful classes used downstream:

- **Not Magnetotail**
- **South Lobe**
- **North Lobe**

Magnetopause boundary crossings are inferred from transitions in the first-stage magnetotail classification.

## Installation

Python 3.12 is recommended. The final analysis was tested with Python **3.12.11**, pandas **2.3.1**, NumPy **2.5.3**, scikit-learn **1.7.1**, and XGBoost **3.0.1**.

Create and activate a virtual environment if desired, then install the dependencies:

```bash
pip install -r requirements.txt
```

## Running the project

There are two ways to use the repository.

### Option 1 — Quick reproduction from processed data

The repository can include the smaller processed inputs required for the ML and spatial-analysis stages. This avoids downloading the full raw spacecraft dataset.

Run:

```bash
python src/part2_generate_unsupervised_labels.py
python src/part3_magnetosphere_spatial_analysis.py
python src/part4_supervised_ml_model.py
```

Part 2 starts from:

```text
data/part1/FULL_merged_df.csv
```

Part 3 additionally uses the coordinate and bow-shock files in `data/part3/`.

Part 4 additionally uses the alpha / K-S distance files in `data/part4/`.

### Option 2 — Rebuild the raw-to-label pipeline from mission data

To regenerate the core THEMIS dataset and unsupervised labels from the public mission archive, begin with Part 0:

```bash
python src/part0_download_raw_data.py
python src/part1_preprocess_hourly_data.py
python src/part2_generate_unsupervised_labels.py
```

Part 0 downloads the required THEMIS mission data using **PySPEDAS** and stores it locally under:

```text
data/part1/raw_data/
```

Part 1 converts those files into aligned hourly data and produces:

```text
data/part1/FULL_merged_df.csv
```

Part 2 then regenerates the THB/THC magnetotail labels in `data/part2/`.

The raw download is large and requires substantial local disk space, so the generated raw/intermediate files are excluded from version control by `.gitignore`.

Parts 3 and 4 can then be run using the auxiliary inputs supplied in this repository:

```bash
python src/part3_magnetosphere_spatial_analysis.py
python src/part4_supervised_ml_model.py
```

Part 3 additionally requires the spacecraft coordinate and bow-shock crossing files in `data/part3/`. Part 4 additionally requires the alpha / K-S distance files in `data/part4/`. These auxiliary files are not generated by Parts 0–2.

## Unsupervised classification

Part 2 performs hierarchical K-means clustering.

### Stage 1 — Magnetotail membership

Features:

- plasma velocity magnitude
- plasma number density

The two fitted clusters are interpreted physically as:

- outside the magnetotail
- inside the magnetotail

For reproducibility, K-means explicitly uses `n_init=10`. This avoids changes caused by later scikit-learn versions changing the default K-means initialisation behaviour.

### Stage 2 — Lobe classification

Samples classified inside the magnetotail are clustered using:

- magnetic-field clock angle
- magnetic-field cone angle

The fitted clusters are mapped to:

- South Lobe
- North Lobe

Cluster meaning is assigned from the fitted physical cluster centres rather than relying on arbitrary K-means cluster numbers.

## Spatial boundary analysis

Part 3 combines the current Part 2 labels with GSM spacecraft coordinates and independently identified bow-shock crossing times.

It produces:

- Y-Z magnetosphere cross-section
- X-Y projection
- X-Z projection
- fitted magnetopause and bow-shock boundary statistics

The main outputs are written to `figures/` and `results/part3/`.

## Supervised classification

Part 4 trains an **XGBoost** classifier using:

- Unix time
- alpha
- K-S distance
- clock angle
- cone angle

The primary model uses an 80/20 random train/test split and the final hyperparameters selected during the original MSc analysis.

### Primary test performance

| Metric | Result |
|---|---:|
| Accuracy | **96.6%** |
| Balanced accuracy | **88.9%** |
| Macro F1 | **0.909** |
| Not Magnetotail recall | **98.7%** |
| South Lobe recall | **83.7%** |
| North Lobe recall | **84.3%** |

The majority-class baseline accuracy is approximately **86.0%**, so minority-class performance is reported alongside overall accuracy.

### Robustness checks

Two additional checks are included:

| Experiment | Accuracy | Macro F1 |
|---|---:|---:|
| Random split, all features | 96.6% | 0.909 |
| Random split, **without Unix Time** | 96.1% | 0.893 |
| Chronological holdout | 90.5% | 0.621 |

Removing Unix time causes only a small reduction in performance, indicating that the classifier is primarily using the physical features. The chronological holdout is substantially harder and highlights temporal distribution shift in the dataset.

## Reproducibility note

During post-project refactoring, a change in the default behaviour of `sklearn.cluster.KMeans` was found to substantially alter the THC clustering. The original MSc analysis effectively used 10 K-means initialisations, while newer versions can use fewer depending on `n_init`.

The GitHub implementation therefore explicitly sets:

```python
n_init=10
```

and assigns physical cluster meaning from the fitted cluster centres. This makes the unsupervised labelling substantially more reproducible across software environments.
